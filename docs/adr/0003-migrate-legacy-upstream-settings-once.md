# Migrate legacy upstream settings once

When the profile database is empty and the legacy upstream fields form a profile that passes the current Base URL, proxy, header-value, and timeout validation rules, the application backs up the JSON, imports those fields as one profile, reduces protocol-specific proxy fields to the effective proxy for that URL, and removes the legacy fields after the database transaction succeeds. If the Base URL is empty and all other legacy values are empty or unchanged defaults, the application backs up the JSON and atomically removes the placeholders without creating a profile. If credentials, a proxy, a non-default User-Agent, forwarding, timeout, or another meaningful setting remains without a Base URL, migration fails and preserves the JSON for manual correction. Validation failure and a conflict with a non-empty profile database likewise preserve the original JSON. Keeping only the backup and the SQLite record after a successful migration avoids an ongoing dual source of truth while still providing a recovery path for upgrades and downgrades.
