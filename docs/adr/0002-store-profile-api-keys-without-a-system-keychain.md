# Store profile API keys without a system keychain

API keys are stored with upstream profiles in the per-user SQLite database and protected through file permissions, masked UI, exports redacted by default with an explicit plaintext-secret export option, and strict exclusion from logs and status responses. On POSIX systems, application-created configuration directories and sensitive database, WAL/SHM, backup, configuration, and export files are owner-only; existing custom directory permissions are preserved. Windows relies on the current user's AppData ACL by default, while ACL isolation for an explicitly selected custom or shared path remains the user's or administrator's responsibility. This preserves the existing authorization behavior and keeps Linux, Windows, macOS, and AppImage packaging consistent without introducing platform-specific keychain dependencies; a future keychain migration remains possible if the additional deployment complexity becomes acceptable.
